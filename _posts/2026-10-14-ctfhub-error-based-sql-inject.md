# 报错注入
**题目来源**: CTFHub
**题型**: Web
**难度**: 简单

## 解题思路
1. 判断注入点：传入参数 `id=1'` 页面爆出SQL错误信息，页面打印数据库报错详情，确认存在单引号字符型注入漏洞，并且可以使用报错注入。
2. 测试payload：尝试使用 `updatexml` 和 `extractvalue` 函数进行注入。经测试，该靶场为高版本 MariaDB，官方已彻底移除上述函数，Payload 触发 SQL 语法错误。
3. 继续尝试：尝试使用 `floor(rand(0)*2)` 配合 `group by` 产生主键冲突报错，因 MariaDB 严格模式（`ONLY_FULL_GROUP_BY`）限制，同样报语法错误。尝试使用新版 `gtid_subset` 函数，受限于数据库版本和 URL 注释符（末尾空格被浏览器吞掉）双重限制，未能回显。
4. 环境说明：CTFHub 报错注入为动态靶机，每次重置环境 Flag 随机变化，旧 Flag 无法提交。此题暂时跳过，留待后续使用脚本盲注攻克。

## 关键操作
> 报错注入极度依赖数据库版本、数据库严格模式、可用函数，环境局限性极强；不同 MySQL / MariaDB 版本支持的报错函数完全不同，不存在通用万能Payload。

## 总结
本题考察SQL报错注入，通过测试多种报错注入Payload，发现受数据库版本、严格模式、函数删减、URL解析规则多重限制，常规手工报错注入方式在本题全部失效，需要根据实际数据库环境选择合适的注入方法。
